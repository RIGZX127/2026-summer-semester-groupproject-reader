# Mercury 全局主题与视觉细节优化设计

## 1. 背景与目标

当前 Phase 2 UI 已具备三栏布局、Reader 工具栏和局部阅读主题，但应用外壳仍采用固定浅色样式，深色选项仅影响 Reader 内容。按钮的交互状态、危险操作、键盘焦点和深色适配也缺少统一规则。

本轮设计将 Mercury 建立为一套完整的“温润现代”双主题界面。目标是让浅色模式具有克制的纸张感，让深色模式适合夜间长时间阅读，同时提高按钮、输入框、列表、工具栏和对话框的一致性、辨识度与可访问性。

## 2. 范围

本轮包含：

- 全应用浅色、深色语义化设计 token。
- “跟随系统 / 浅色 / 深色”三种主题偏好及持久化。
- 主窗口、侧栏、文章列表、Reader、工具栏、对话框、状态栏、菜单、滚动条和页面状态的主题适配。
- 按钮和输入控件的完整交互状态及可访问属性。
- Reader HTML 与应用外壳的主题同步。
- 与主题和视觉状态有关的自动测试及人工验收。
- 完成里程碑后的 `AGENTS.md` 状态和设计决策更新。

本轮不改变 Feed 同步、Reader 内容管线、数据库 Schema 或 Agent 业务行为，也不新增标签、笔记或设置面板等业务功能。

## 3. 视觉方向

采用已确认的 A 方案“温润现代”。界面以低饱和青绿作为品牌强调色，以暖米白和墨绿灰分别构成浅色与深色阅读环境。颜色不做机械反相，两套主题分别校准背景、正文、次级文字、边框、悬停面和状态色。

### 3.1 浅色主题

- 窗口与 Reader 背景使用暖米白，避免冷白造成的屏幕感。
- 列表、工具栏和输入控件使用略有明度差异的柔和灰白表面。
- 正文使用深蓝灰，次级文字使用中性灰蓝。
- 侧栏保留深墨蓝作为品牌视觉锚点。
- 主强调色采用低饱和青绿，警告色采用暖琥珀，错误色采用低饱和红。

### 3.2 深色主题

- 主窗口与 Reader 使用低亮度墨绿灰，不使用纯黑。
- 列表、工具栏、输入框与悬停面使用逐级提亮的炭绿色表面。
- 正文使用柔和暖灰白，不使用纯白；次级文字使用灰绿色。
- 侧栏与整体墨绿色统一，以明度和选中面区分层级，避免粗重边框。
- 强调色使用较亮但低饱和的青绿，保证在暗背景上清晰且不刺眼。
- 状态色使用深色专用值，确保成功、警告和错误信息可辨识。

### 3.3 对比度与状态表达

- 正文、按钮标签和输入文字至少满足 WCAG AA 对比度。
- 已读、收藏、同步、错误和禁用状态不得只依赖颜色，必须配合文字、图标、字重或形状。
- 分割线仅用于必要的结构边界，优先通过表面明度差建立层次。

## 4. 全局主题行为

主题偏好包含三个值：

- `system`：默认值，跟随操作系统配色方案。
- `light`：固定使用浅色主题。
- `dark`：固定使用深色主题。

偏好通过 `QSettings` 保存。主题管理器将用户偏好解析为当前有效主题，并统一向应用 QSS 与 Reader HTML 提供有效主题。当偏好为 `system` 时，操作系统主题变化应在运行时更新整个界面；若当前平台或 Qt 版本无法可靠发出变化事件，则至少在应用启动和设置变更时重新解析系统主题。

切换主题时不改变当前 Feed、文章、Reader 模式、滚动位置、字号或内容宽度。主题更新不得触发网络请求、数据库写入或 Reader 内容重新抓取。

## 5. 设计 token 与组件边界

`app/styles.py` 提供浅色和深色两套语义化 token。组件只能引用语义角色，不直接依赖具体十六进制颜色。主要角色包括：

- `window`、`surface`、`surface_alt`、`surface_hover`、`surface_pressed`
- `sidebar`、`sidebar_hover`、`sidebar_selected`
- `text`、`text_muted`、`text_disabled`、`text_on_accent`
- `border`、`border_strong`、`focus`
- `accent`、`accent_hover`、`accent_pressed`、`accent_soft`
- `success`、`warning`、`error` 及其柔和背景色

主题管理器负责偏好持久化、系统主题解析、有效主题变更通知和 QSS 更新。Reader 主题管理器继续负责字号、内容宽度和正文 CSS，但颜色来源改为全局有效主题，避免应用外壳与正文出现浅深色不一致。

## 6. 按钮与控件设计

### 6.1 按钮层级

- 主按钮：青绿色实心背景和暖白文字，用于添加订阅、重试等明确主操作。
- 次按钮：低对比表面色和细边框，用于普通操作。
- 工具栏按钮：默认透明或弱表面背景，悬停时显示柔和底色。
- 分段按钮：Reader/Web/双栏模式形成一体化分段控件，选中项使用完整强调色块。
- 危险按钮：静止状态保持克制，只在危险上下文、悬停或确认区域显示低饱和红色。

### 6.2 完整状态

所有按钮至少定义 `normal`、`hover`、`pressed`、`checked`、`focus` 和 `disabled`。按下态通过加深背景与约 1px 的视觉位移形成触感；禁用态降低文字与边框对比度，但仍保持文字可读。

键盘焦点使用清晰而柔和的青绿色描边，不能仅依赖背景变化。普通按钮和输入控件的最小高度为 36px；纯图标按钮的最小点击区域为 36×36px。

### 6.3 圆角与空间

- 普通控件圆角为 8px。
- 卡片与主要面板圆角为 12px。
- 状态徽章使用胶囊圆角。
- 控件内部和组件间距遵循 4px/8px 基础网格，避免局部出现不一致的紧凑度。

纯图标按钮必须提供 Tooltip 和可访问名称。焦点顺序应遵循从侧栏、文章列表到 Reader 工具栏和正文的阅读顺序。

## 7. 页面与组件适配

- 主窗口：窗口背景、分栏边界和状态栏使用当前有效主题。
- 侧栏：标题、Feed 行、未读角标、同步状态和错误状态在两套主题中均保持清晰。
- 文章列表：搜索框、选中行、未读标题、摘要、时间、收藏和右键菜单完整适配。
- Reader 工具栏：模式分段控件、字号、主题和宽度控件使用一致的按钮与输入样式。
- Reader HTML：正文背景、标题、元数据、链接、引用、代码块、表格和图片说明使用全局主题颜色。
- 对话框：添加订阅、确认删除和错误提示不得保留平台默认的突兀浅色区域。
- 页面状态：empty、loading、content、error、offline、disabled 均使用主题 token，并保留文字或图标说明。
- 滚动条和菜单：使用低干扰样式，但在悬停、拖动与键盘操作时清晰可见。

## 8. 错误处理与兼容性

- 无法读取系统主题时回退到浅色模式，并保留用户的 `system` 偏好，以便后续启动重新解析。
- 无效或旧版主题设置值回退到 `system`，不得导致启动失败。
- QSS 更新或 Reader CSS 生成失败时记录开发者可读错误，并保持上一套有效样式，避免界面变成无样式状态。
- Windows、macOS 和 Linux 使用同一语义 token；平台差异只允许出现在主题检测适配器中。
- 高 DPI 下不得使用依赖位图缩放的按钮图标；优先使用 Qt 标准图标或可缩放矢量资源。

## 9. 测试与验收

### 9.1 自动测试

- 三种主题偏好的保存和恢复。
- `system` 偏好到浅色或深色有效主题的解析。
- 运行时主题切换会更新应用 QSS 和 Reader CSS。
- 无效设置值的安全回退。
- 浅色与深色 QSS 均包含按钮六种状态及关键组件选择器。
- Reader 模式、字号和内容宽度在主题切换后保持不变。
- 图标按钮具有 Tooltip 和可访问名称。
- 现有 UI、Reader、Feed 和 Store 测试保持通过。

### 9.2 人工验收

- 分别在浅色和深色下检查主窗口、侧栏、文章列表、Reader、对话框、菜单、状态栏和滚动条。
- 检查按钮正常、悬停、按下、选中、焦点和禁用状态。
- 检查空、加载、错误、离线和禁用页面状态。
- 在夜间环境连续阅读正文，确认背景不发黑、文字不刺眼、次级信息仍清楚。
- 检查中英文长文本、键盘导航、Windows 125%/150% 缩放以及 macOS/Linux 常见缩放。

## 10. 完成标准

当全应用主题切换、系统跟随、持久化、Reader 同步、按钮状态、组件覆盖、自动测试和人工验收全部满足本规格，并在重要里程碑后更新 `AGENTS.md`，本轮视觉优化才视为完成。
